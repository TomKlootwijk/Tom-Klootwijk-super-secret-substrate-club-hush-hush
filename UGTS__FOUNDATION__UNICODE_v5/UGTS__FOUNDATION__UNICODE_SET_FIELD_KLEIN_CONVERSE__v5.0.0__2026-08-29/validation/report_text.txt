FORMAL DECISION
Release UGTS Foundation 5.0 as a component-scoped major version. The literal Unicode operator becomes the cold-atlas key for a content-addressed OperatorCell that
co-addresses exact Unicode spelling, typed syntax, semantic evaluator, canonical
glyph SDF, signed set-field action, converse relation, Klein reflection rule, exactness
capability, provenance and content hash. Geometry and semantics remain distinct
typed faces; they are not collapsed into one notion of equality.
VERIFIED RELEASE RESULT
The accompanying package supplies 20 hash-verified OperatorCells; a 16-slot setrelation hot codebook with 14 assigned converse slots and two reserved slots;
a corrected Packed Set-Field Node 32 codec; binary stream framing with CRC; a
dependency-free Python reference runtime; portable C++20 scalar packing; an optional AVX2 extraction profile; JSON Schemas; a 64-mechanism delta; a 24-row claims
ledger; runnable examples; a wheel; and captured validation evidence. The release
test suite contains 83 passing Python tests. Three JSON instances validate with zero
errors, and the native scalar codec test passes.
MAJOR-VERSION CONCLUSION
A Unicode operator is no longer merely text and no longer merely an icon. It is a
content-addressed, executable geometric rule cell whose literal codepoint resolves
both its canonical shape and its typed operation. A Klein-converse parity flip mirrors
the shape, reverses the typed ports and selects the converse Unicode spelling while
preserving the mathematical truth value.
EVIDENCE BOUNDARY
The immediate source document correctly identifies ∋ as the converse spelling of ∈,
proposes geometric operator primitives, log-polar fixed-point packing, a 32-bit node
and SIMD decoding. It also contains packing errors, overloaded parity, incomplete
geometry, and unsupported universal compression, speed, randomness and physical
claims. Version 5.0 does not silently clean the source into a fictional proof. Every major
claim is admitted, corrected, bounded or rejected in the machine-readable claims
ledger. [S0]

1 Major Release Identity and Scope
1.1 Why this is a major version
Version 5.0 changes the unit of formal operator identity. Earlier releases already established content-addressed definitions, representation profiles, log-polar packing, explicit reflective topology, general typed operators and field-capability boundaries. This release
unifies those commitments in a new foundation component whose central object is the
Unicode-addressed executable operator cell.
The major change is not a larger list of symbols. It is a stronger invariant:
The exact Unicode literal is a stable lookup key into one record that carries syntax, typed semantics, canonical geometry, field behavior, converse topology and execution metadata.
A change in font outline does not silently change set membership. A change in operand
spelling from 𝑥 ∈ 𝐴 to 𝐴 ∋ 𝑥 does not create a second mathematical relation. A packed
four-bit slot does not replace the global Unicode identity. These distinctions now belong to
the formal release schema rather than explanatory prose.

1.2 Component-scoped identity
The versioning charter deprecates a single global ladder because compute profiles, foundations, runtimes, formal packs, applications and platform builds are not globally comparable.
Version 5.0 therefore uses the canonical identity
ugts.foundation.unicode-set-field-klein-converse@5.0.0.
The legacy alias UGTS-KC 5.0 remains for discovery. The parent graph records exactly
which releases contribute architecture; it does not claim that this foundation supersedes
unrelated game, scanner, solver or device branches. [S7]

2.2 Immediate source dissection
The immediate source contributes five technically useful motifs:
1. ∈ and ∋ are converse surface spellings of one membership relation.
2. Unicode operator shapes can be described by bounded geometric primitives.
3. local geometry can be addressed in log-polar coordinates and packed into fixed-width
records.
4. a one-bit selector can choose between declared orientations or relation directions.
5. SIMD extraction can decode several packed words in parallel.
It also requires explicit correction:
• The source’s example LUT selects codepoints by quadrant rather than evaluating the
advertised glyph SDFs.
• One packing expression overlaps angle and codepoint bits.
• The proposed 32-bit decoder extracts the parity bit but does not verify payload parity.
• The active bit is omitted by one unpacker.
• A Boolean value of 0 or 1 is not a valid full byte/lane mask for blendv; it must be expanded.
• A deterministic parity bit is not true randomness, anti-aliasing proof, complete state or
cryptographic entropy.
• A half-turn rotation is not an orientation-reversing Klein gluing.
• Universal 16 KB, constant-time, cycle-count and collision-free-path claims are not established.

For membership, the canonical semantic ports are

a parser special case.

4.4 Three faces, one address
The release enforces
𝐺𝑈 ≠ 𝐸 𝑈 ≠ 𝐹 𝑈 ,
yet resolves all three through the same literal cell. A glyph sample does not decide membership. A semantic truth value does not imply zero geometric glyph distance. A set-field
transform does not establish a font’s outline. The co-addressing is a referential convenience
with typed boundaries, not a claim of cross-domain identity. [S2]

4.5 Content addressing
Each cell hash is computed from canonical UTF-8 JSON with sorted keys, NFC strings and no
non-finite numbers, excluding only the hash field itself. The atlas hash commits to all cells
and atlas metadata. A codebook commits to the atlas hash and each occupied operator-cell
hash.
BOUNDARY
A SHA-256 content address identifies bytes under the canonicalization policy. It is not
legal authorship, ownership, priority, semantic truth or collision-free identity across
every possible future policy.

10.2 Packing formula

Bit 31 equals the population parity of bits 0–30, giving even parity over the full word.

11 Scalar and SIMD Execution Profiles
11.1 Scalar oracle
The dependency-free Python and C++20 scalar codecs are the conformance authority. Every backend must match:
• field extraction and signed Δ𝜌 decoding;
• active and local flags;
• operator family and 𝜅;
• parity verification;
• Klein flip and round trip;
• codebook resolution;
• error and capability status.

11.2 AVX2 eight-lane extraction
The optional header native/ugts5_avx2.hpp loads eight words and extracts fields with
shifts and masks. It corrects two common source errors:
1. reading bit 31 is not parity verification; a tested popcount/XOR fold or scalar check is
still required;
2. a 0/1 selector must be expanded to 0x00000000/0xffffffff before lane-wise selection.
The reference mask expansion is conceptually
𝑀 = 0 − 𝜅,
so each 32-bit lane becomes all-zero or all-one.

11.3 ARM NEON profile
The NEON contract mirrors the AVX2 layout in four lanes and uses full-lane masks before
vbslq_u32. It is specified but not measured in this package.

11.4 Branch strategy
Evaluate-both-and-select can help when both branches are cheap and coherence is poor.
It can waste work when either branch is expensive. A backend may choose among scalar
branching, active-lane compaction, dual evaluation or measured automatic selection. No
universal speed claim is promoted.

12 Exactness, Proof and Certification
12.1 Point query versus global relation
A point membership query can be a local field comparison. Subset, equality and emptiness
are global relations:
𝐴 ⊆ 𝐵 ⟺ ∀𝑥 ∈ 𝑋 ∶ 𝑥 ∈ 𝐴 ⇒ 𝑥 ∈ 𝐵.
No packed local lookup turns the quantifier into universal constant-time proof.

12.2 Certificate object
A version-5 relation certificate contains:
𝐶 = (𝑈 , ℎ𝑈 , profile, operands, scope, capability, 𝐼, 𝑒, 𝑚, 𝑟, 𝑁 ),
where 𝐼 is the result or interval, 𝑒 numeric error, 𝑚 event margin, 𝑟 reason/status and 𝑁
explicit non-claims.

12.3 Finite exact proof
For a declared finite universe, the runtime can exhaustively check membership, subset,
proper subset, equality and emptiness. The universe ordering is part of the proof input.
Changing the universe invalidates the certificate.

12.4 Continuous proof
A continuous-domain claim requires at least one of:
• an analytic proof;
• interval arithmetic covering the full domain;
• a certified spatial subdivision with a proven residual bound;
• a theorem-specific decision procedure;
• another explicitly verified completeness argument.
A sampled LUT remains sampled evidence unless the certificate closes the between-sample
gap.

13.1 Pure evaluation is upstream

13.3 Example: membership-triggered transition
Suppose a rule proposes opening a gate when token 𝑥 belongs to set 𝐴. The OperatorCell
answers 𝑥 ∈ 𝐴. The application must still prove that the rule is supported at this gate, the
token and gate are compatible, timing and uncertainty guards pass, and the resulting patch
preserves required invariants. Only then is the gate state committed.

13.4 Example: reflective route transition

verify. Winding and the selected quotient remain in lineage so repeated arrivals at the
same coordinates are distinguishable.

UGTS Foundation 5.0 is a literal, content-addressed Unicode operator substrate in

MAJOR-VERSION CONCLUSION
A Unicode operator is no longer merely text and no longer merely an icon. It is a
content-addressed, executable geometric rule cell whose literal codepoint resolves

the shape, reverses the typed ports and selects the converse Unicode spelling while
preserving the mathematical truth value.
