# Evidence boundary

The supplied reports separate source-derived mechanisms, engineering normalization, measured package evidence and rejected/unsupported claims. UGTS-KC 2.0 keeps that separation.

- **Baseline:** M001-M197 and the canonical support/compatibility/guard/event/transition/lineage pipeline are taken as the existing normalized substrate.
- **Engineering additions:** M198-M257 are new constructions chosen because they can be represented as typed curves, fields, topology maps, kinematic operators, state transitions or measurable dynamics.
- **Implemented evidence:** only functions and tests shipped in this package are marked implemented.
- **Specified only:** knot/link certification and persistent-homology computation are described by exchange contracts but not presented as solved by the bundled code.
- **Physical boundary:** mathematical minimal surfaces, topology labels and dynamic models do not imply free energy, zero loss, self-assembly or hardware advantage.
- **Complexity boundary:** closed-form state queries can skip frame materialization for restricted families, but expression size, event density, branch resolution and numerical conditioning still cost resources.
